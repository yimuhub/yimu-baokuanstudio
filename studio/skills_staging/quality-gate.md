# Skill：发布质检

> 移植自项目 A `app/quality.py`（score_draft / score_prescore / score_review）。
> 分层：纯文本初筛 → 六维打分 → 终审（加配图符合度）。

## 适用场景

- 初稿/仿写稿发布前的最后一道关
- 给改写环节提供按维度拆开的修改建议

## 输入

- 成稿 draft；`platform` 平台码；配图信息（终审用，可选）

## 输出

`{total, level, publishable(≥75 可发布), dims 六维, suggestions, human}`；
终审加 `cover_fit` 配图符合度。

## 核心规则

### 6 维权重

| 维度 | 权重 | 看什么 |
|------|------|--------|
| title | 20 | 标题吸不吸睛 |
| hook | 20 | 开头 3 行留不留人 |
| value | 25 | 信息增量够不够 |
| layout | 15 | 小标题/分段/节奏 |
| fit | 10 | 平台调性匹配 |
| safe | 10 | 合规与事实安全 |

### 档位线

- < 75 不合格 / 75–84 及格 / 85–94 良好 / ≥ 95 优秀
- `publishable` = total ≥ 75

### 平台篇幅目标（字）

公众号 800–2200 / 小红书 200–1000 / 微博 20–300 /
知乎 800–3000 / 掘金 800–2500 / 头条 800–2200

### 兜底规则

- 待填空标记未填 → value −15 且 safe 降到 55（"没换 = 没写完"）
- 命中套话词表 → safe −15
- 小标题 ≥ 2 个 → layout 给 85

### 人味锚点（独立判定）

`human.check(draft)` 单独输出人味结论，**不并入 total**——
75/95 及格线是对外承诺，不偷偷改分。判据（套话词表/待填空标记检查）复用唯一事实来源。

### 终审配图分

≥ 3 张图 90 / ≥ 1 张 80 / 无配图信息 50；
review 总分 =（文本加权分 + 配图分 × 10）/ 110。

## 质量门

- [ ] total < 75 一律不予发布（红灯）
- [ ] 人味结论独立展示，不许并入总分"凑"及格线
- [ ] 待填空标记未填的稿子，value/safe 按规则扣分，不许手软放行
- [ ] 评分建议必须具体到维度（如"hook：开头 3 行无钩子，建议加数据式开头"），不许只给总分
