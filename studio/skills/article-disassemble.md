# Skill：爆款拆解

> 移植自项目 A `app/structure.py`（analyze_structure / synthesize_skeleton）。纯规则，可离线运行。

## 适用场景

- 拿到一篇爆款，想知道它"为什么火"（结构层面的可复用骨架）
- 批量拆多篇同领域爆款，归纳共性骨架，供仿写环节套用
- 给选题作业单配"对标骨架"

## 输入

- 单篇拆解：一篇爆款正文 text（< 200 字拒绝拆解，太短没有结构信号）
- 批量归纳：多篇正文 texts[]

## 输出

- 单篇：结构化特征（钩子类型 / 收尾类型 / 小标题列表 / 段落数 / 信息密度 / 首个案例段落 / 密度曲线）
- 批量：共性骨架 + 推荐模板（4 选 1）

## 核心规则

### 开头钩子 7 类（命中取首个，无命中记"直述式"）

疑问式 / 数据式 / 场景式 / 结论前置 / 引语式 / 故事式 / 对比式

### 收尾 5 类

号召互动 / 总结收束 / 提问收尾 / 悬念预告 / 引用收束

### 小标题判定

1. Markdown 的 `##` 行优先认作小标题
2. 纯文本看编号（中文数字 / 阿拉伯数字 / 带圈数字 / "第 X 部分"）+ 短行（≤ 18 字且不以句号结尾）
3. 分隔线（`---`）明确不是小标题

### 信息密度

- `numbers_per_1k`：每千字数字个数；`quotes_per_1k`：每千字引用个数
- `density_curve`：段落长度归一到 0–9 的密度曲线
- `first_case_para`：首个案例出现在第几段（案例前置是强信号）

### 骨架模板 4 套与选用规则

1. 钩子—痛点—方案—案例—收尾
2. 结论前置—分层论证—反例—收束
3. 故事开场—转折—方法—号召
4. 清单式—并列展开—收尾清单

选用规则：小标题多的走「结论前置」，案例靠前的走「故事开场」，否则默认第一套。

## 质量门

- [ ] < 200 字的正文不拆（直接返回 ok=False，拒绝硬拆）
- [ ] 钩子/收尾类型必须命中规则表，命中不了就标"直述式"，不编造分类
- [ ] 批量归纳时骨架必须来自真实样本统计，不允许凭空拼模板
