2.1 用户与会员管理:首次进入永远「正在加载用户数据…」P1

复现路径:刷新页面 → 控制中心 → 用户与会员管理。表格永远停在加载占位,右上角一直「加载中…」。接口本身完全正常(GET /api/admin/users 实测 200 / 14ms / 5 条),手点「↻ 刷新列表」立即出数据。

web/templates/index.html:11249(懒加载闸门漏了一个子面板):
function gwNEnsureLoaded(sp){
  if(_gwNLoaded[sp])return;_gwNLoaded[sp]=true;
  if(sp==='sp-gateway'){gwNLoadUpstream();gwNLoadKeys();}
  if(sp==='sp-billing'){blNLoadMe();blNLoadLedger(true);}
  if(sp==='sp-user-admin'){loadAdminUsers(0);}
}
web/templates/index.html:11252(switchSubTab 内的调用条件把它挡住了):
if (typeof gwNEnsureLoaded === 'function' && (subId === 'sp-gateway' || subId === 'sp-billing')) {
  // ← sp-user-admin 不在条件里,进入「用户与会员管理」永远不触发加载

2.2 TTS 配音合成成功,但音频播放 404P1

实测路径:影音工坊 → AI 口播配音 TTS → 输入 16 字 → 生成口播音频。合成本体成功(文件 247KB 落盘,任务 done),但播放器 MEDIA_ERR_SRC_NOT_SUPPORTED(error 4)——前端拿到的 URL 404。

根因(URL 契约断裂,三处对不上):
core/audio.py:89,100      返回 url = f"/audio/{draft_id}/{produced.name}"   ← V7 时代遗留格式
web/routers/files.py:32   路由是 /audio/drama/{did}/{filename}(且只服务 drama/audio/ 子目录的短剧音频)
web/routers/media.py:116  真正能用的路由是 /api/audio/file/{did}/{name}(实测 200 / 247KB)
前端 audio.src = res.audio_url → /audio/dr-xxx/audio-30s-.mp3 → 404

修复(两行):core/audio.py 两处 url 改为 /api/audio/file/{draft_id}/{name};顺带删除或对接 files.py 里从未被 TTS 命中的 /audio/drama/... 之外的歧义。PC 与移动端同源受益(URL 由后端下发)。

TTS 面板:16 字 · 预计 4 秒 · 播放器已挂载但 src 404——「生成成功、一播放就哑」的组合对用户最有迷惑性。

4.2 量化审计:五处大头(全部带实测数据)

  1. gzip level 9 同步阻塞事件循环【1 行改动,收益最大】:GZipMiddleware 默认 compresslevel=9(admin.py:79),压一次 index.html 实测 33.1ms CPU(level 6 = 18.3ms,输出仅差 2%);压缩在 ASGI send 链上同步执行,期间整个 worker 停摆——10 QPS 首页即吃掉 ~1/3 个核,所有并发接口被拖住。
  2. GET //m 每请求全量读盘 + 7 次字符串替换 + importlib.reload(admin.py:2030-2032, pages.py:57-62):render 6.95ms + reload 0.5-2ms + Cache-Control: no-store 使每次导航全额重付。修复:按 (mtime, version) 缓存渲染结果。
  3. i18n 1771 条短语线性扫描,连中文模式也在跑(i18n.js):zh 启动即全 body 遍历走 REVERSE_PHRASE_LIST 1763 次循环,数千文本节点 ≈ 主线程阻塞 200-600ms(桌面)/ 0.5-1.5s(低端手机);EN 模式 MutationObserver 每次任务抽屉重绘(2s 一次 × 450 文本节点)≈ 50-200ms。修复:短语表编译为单条交替正则 + zh 模式跳过全量 walk。
  4. 无索引的全表扫描 ×2:async_tasks(created_at ORDER BY 实测 SCAN + TEMP B-TREE)与 topics(workspace_id, created_at 实测 13.3ms/次);每次轮询还全量 json.loads params/result 大列。修复:两条 CREATE INDEX + 列表查询裁掉大列。
  5. 每请求重复读盘:desktop 免密模式下每个 /api/* 走 _admin_password → load_env → 读 2 个 env 文件(无缓存);/api/status 单请求约 10 个新建 SQLite 连接 + 每草稿 6-8 次文件 stat。修复:env() 加 mtime 缓存;capability 解析合并为 1 次。
