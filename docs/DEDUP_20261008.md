## 三、性能优化（实测数据）

### 3.1 技能库读取缓存（`core/agents.py::list_skills`）

**问题**：每次调用读 68 个 .md 文件 + YAML 解析。调用方：`/api/skills/all`（页面每次打开）、`orchestrator`（每次改写）、`copilot`（每次对话）。

**修复**：mtime 缓存——key =（目录 mtime，文件数，文件最大 mtime），三者任一变化自动失效。

**实测**：
- 首次（磁盘）：16.5ms → 缓存命中：0.50ms（**33 倍**）
- 文件修改后自动失效重读（已验证）

### 3.2 GZip 压缩（`web/admin.py`）

**问题**：`index.html` 835KB（JS 417KB + CSS 85KB + HTML 264KB），无压缩中间件。

**修复**：`app.add_middleware(GZipMiddleware, minimum_size=1000)`。

**效果**：首屏 HTML 835KB → ~140KB（gzip 典型压缩比，本地回环主要省解析与传输）。

### 3.3 未动的高风险项（记录，不碰）

- `list_drafts()` 取 `body_md`（200 条全文）：前端列表页用 `body_md` 做关键词搜索与字数统计，移除会破坏搜索。改为服务端搜索属大重构，暂不碰。
- `index.html` 拆分：83 万字节单文件，拆分需前后端联动重构，风险高。GZip 已缓解传输问题。
- `studio/db_models.py` 导入 53ms：SQLAlchemy 声明式固有开销，正常范围。
