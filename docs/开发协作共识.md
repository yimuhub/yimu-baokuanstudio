## 一、Git 协作开发标准规范（SOP）

团队所有成员及 AI 助手在进行任何功能迭代、Bug 修复、重构或架构升级时，必须严格执行以下工作流：

### 1. 提交前同步与冲突对齐（Sync Before Commit）
- **检测远端更新**：在准备提交或推送前，首先检查远端是否有其他协作者提交的新代码：
  ```bash
  git fetch origin
  git status
  ```
- **拉取与平滑合入**：若远端存在更新，执行 `git pull --rebase origin <branch>`，在本地完成对齐与冲突解决，确保提交图线整洁清晰，严禁暴力强推（`--force`）。
- **本地改动精细审查**：
  ```bash
  git diff
  git status
  ```
  仔细核验每一个文件的改动，确保没有多余的临时调试文件、未脱敏的 API Key、测试临时数据落盘。

### 2. 规范化提交（Semantic Commit Messages）
- 每次提交必须使用语义化前缀，格式示例：
  - `feat(模块名): 新增功能描述`（如 `feat(aivideo): 增加数字人形象记忆库与一键复用`）
  - `fix(模块名): 修复问题描述`（如 `fix(voice-clone): 修复声音克隆服务协议解析与保底链路`）
  - `docs(文档): 补充或修正文档`
  - `test(测试): 补充单元测试或自动化回归用例`
  - `refactor(重构): 代码重构与结构优化`
- 提交说明中简要列出主要修改点，让团队成员与后续维护者能一目了然看懂每一步的开发目的。

### 3. 文档同步与可追溯记录（Documentation First）
- 每一个新功能的开发或 Bug 修复，都必须同步在 [**问题修复记录.md**](file:///Users/czmj/Documents/yimu-baokuanstudio/问题修复记录.md) 中追加记录：
  - **卡点/需求**：业务或技术背景是什么？
  - **根因分析**：问题根源在哪里？
  - **解决方案**：采取了哪些代码设计与实现？
  - **验证结果**：通过了哪些单元测试与真机验证？
- 涉及 API 新增或变更时，必须同步更新 [**docs/CONTRACT.md**](file:///Users/czmj/Documents/yimu-baokuanstudio/docs/CONTRACT.md) 维持双向契约锁死。

### 4. CI 门禁与版本号共识
- **CI 门禁 100% 通过**：提交代码前必须执行 `bash ci.sh`，确保以下 4 步全绿：
  1. 单元测试与契约双向锁死（pytest）
  2. 真活探针（判据=产物存在）
  3. 术语合规（无面向用户的内部黑话）
  4. 密钥扫描（无硬编码密钥、无 .env 落盘）
- **版本号升级标准**：
  - 小改 / 体验细节优化：`+0.01`
  - 中等程度功能升级 / 模块新增：`+0.1`
  - 重大架构升级 / 重大里程碑：`+1.0`
  - 维护 [`version.py`](file:///Users/czmj/Documents/yimu-baokuanstudio/version.py) 作为全项目单一版本真源。
- **备份治理**：全项目历史备份严格遵循「只保留最近 5 份」的轮转策略，杜绝磁盘冗余文件堆积。
